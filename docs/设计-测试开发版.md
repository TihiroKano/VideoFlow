## 2. 本机环境约束与工具链决策

| 约束 | 实测 | 决策 |
|---|---|---|
| Rust 工具链 | 未安装 | 安装 `stable-x86_64-pc-windows-gnu` |
| MSVC Build Tools | 未安装，`link.exe` 不存在 | **不安装**（约 3–6 GB，C 盘仅剩 5.1 GB） |
| MinGW-w64 | 未安装 | 安装 WinLibs POSIX/UCRT 到 `D:\rust\mingw-extract` |
| C 盘可用空间 | 5.1 GB | `RUSTUP_HOME`/`CARGO_HOME`/`CARGO_TARGET_DIR`/MinGW 全部指向 D 盘 |
| D 盘可用空间 | 32.8 GB | 全量依赖约 8 GB |

环境变量（构建前必须设置，脚本见 `scripts\env.ps1`）：

```powershell
$env:RUSTUP_HOME      = 'D:\rust\rustup'
$env:CARGO_HOME       = 'D:\rust\cargo'
$env:CARGO_TARGET_DIR = 'D:\rust\target'
$env:PATH             = "D:\rust\mingw-extract\mingw64\bin;D:\rust\cargo\bin;$env:PATH"
```

### ADR-001：使用 GNU 工具链而非 MSVC
Tauri 官方推荐 MSVC，但本机 C 盘余量不足以安装 VS Build Tools。GNU 工具链 + MinGW-w64 可完整编译 Tauri 2，代价是部分 Windows 专属 crate 需验证。若出现无法绕过的 GNU 编译错误，再与用户协商（清理 C 盘后装 MSVC，或降级为 Web 壳层）。

### ADR-002：单 Tauri 应用目录，而非多 crate workspace
项目书 §8 描述 `apps/` + `crates/` monorepo。测试开发版采用 Tauri 标准布局 `src/`（前端）+ `src-tauri/`（Rust），在 `src-tauri/src/` 下按项目书模块名分层（`core`/`resolver`/`downloader`/`scheduler`/`media`/`storage`/`platform`）。理由：单应用无需多 crate 的编译隔离，workspace 会显著增加 GNU 工具链下的构建复杂度与排错成本；模块边界与项目书一致，后续可平滑拆分为独立 crate。

### ADR-003：原生 WebGL2，而非 Three.js
项目书要求"一个全局 Three.js WebGL2 Canvas + Scissor 局部渲染"。本实现直接使用原生 WebGL2 实现同一件事：单 canvas、全屏四边形、Scissor 分区、自定义 SDF/折射/GGX 着色器。理由：该管线是屏幕空间后处理，不需要 Three.js 的场景图与几何管理；原生实现更小、更可控，且完整满足"全局唯一 canvas、禁止每组件一个 context"的硬约束。

### ADR-004：状态管理用 Zustand，不引入 TanStack Query
测试开发版的后端状态通过事件总线（`task.updated` 等）推送，前端只需一个收敛的 store。TanStack Query 的缓存失效模型在此并无收益，反而增加一层心智负担。

## 4. 双引擎下载架构

```text
URL ─→ 校验（scheme/长度/条数/SSRF 内网拦截）
        │
        ▼
   ProviderRegistry
   ├─ DirectProvider   直链媒体（.mp4/.webm/.m4a…）→ HEAD/Range 探测
   └─ YtDlpProvider    站点链接 → yt-dlp --dump-json → 标准化 ResolvedMedia
        │
        ▼
   Scheduler  并发 3（可调 1–6）、优先级、每域名上限、幂等命令
        │
        ├── YtDlpEngine      站点授权流：交给 yt-dlp 下载，解析其进度输出
        └── NativeHttpEngine 直链：Range 分段 8–32 MiB、.part + .resume.json
                             原子检查点、ETag/Last-Modified 校验、EWMA 速度与 ETA
        │
        ▼
   FFmpeg（仅无损 remux / 音视频合并，按需调用）
        │
        ▼
   长度校验 → 同目录临时名 → 原子 rename → file_records → 打开 / 定位 / 回收站删除
```

**合规边界**（项目书 §0.2、§3.1）：不实现 DRM 绕过、登录凭据窃取、付费墙或访问控制绕过；仅处理用户有权下载的公开资源。sidecar 调用使用固定参数数组，禁止 shell 拼接。

**进度事件**：最大 4 次/秒/任务合并推送，前端插值渲染。

## 5. Liquid Glass 渲染设计

合成顺序固定：**静态图片模糊基底 → 液态玻璃容器 → DOM 内容 → 高亮反馈**。

### 档位

| 档位 | 实现 | 关键差异 |
|---|---|---|
| L1 `quality` | WebGL2：单 canvas、全屏 shader | SDF 圆角、倒角高度场、双界面折射（IOR 1.46）、边缘 RGB 色散、三路采样、GGX/Smith/Schlick 光边 |
| L2 `balanced` | WebGL2 降分辨率 RT | 保留折射与形体，关闭色散，简化 Fresnel |
| L3 `performance` | 纯 CSS | 背景图预模糊副本 + 半透明底色 + 1px 内描边 + 静态阴影，**不初始化 WebGL** |

三档共享同一布局、色彩语义与文字对比；档位只改变渲染成本，不改变功能。

### 注册机制

`GlassSurface` 包裹组件声明"我需要玻璃"，`glassRegistry` 通过 ResizeObserver + `getBoundingClientRect` 收集包围盒，`GlassCanvas` 以 Scissor 分区逐块绘制。组件 SDF 坐标按自身尺寸归一化（`p = (uv - .5) * vec2(componentAspect, 1)`），保证窗口缩放、跨 DPI、右栏展开时圆角与倒角不被拉扁。

### 设备探测与降级

`platform/device.rs` 提供 CPU 核心、内存、GPU 与 WebGL2 能力，前端做 120 帧 rAF 微基准取 p95 帧时间；按项目书 §6.2 给出可解释推荐（含 reasons），用户手选永久优先。运行时状态在设置页"渲染状态"显示 `L1/L2/L3` 与当前原因。

## 6. 关键产品决定

| 项 | 决定 |
|---|---|
| 默认下载目录 | `D:\VideoFlow\Downloads`（设置页可改，首次启动自动创建） |

| 格式转换 | **仅 UI**；文件选择、格式/编码选择、队列卡片齐全，提交时明确提示"开发中" |
| 不实现 | 视频/动态壁纸、循环播放、静音、DRM、exe 打包与签名 |
| 视觉复现种子 | 预览图的填充态由 `test/fixtures/` 的开发种子数据复现；默认启动为空状态 |

## 7. 测试策略

全部测试文件置于 `test/`，便于整体删除：

- `test/unit/`：Rust 侧错误分类、URL 校验、分片计算、文件名冲突策略；前端侧纯函数。
- `test/integration/`：原生 HTTP 引擎对本地起的静态服务做 Range/断点续传/取消验证。
- `test/e2e/`：Tauri 窗口启动、三栏渲染、模式切换、队列交互。
- `test/fixtures/`：预览图填充态种子数据、媒体样本。

## 8. 风险

| 风险 | 应对 |
|---|---|
| GNU 工具链编译 Tauri 2 摩擦 | 先做最小窗口编译冒烟验证，失败则提前暴露 |
| yt-dlp 受网站风控/需登录 | 返回明确错误分类与"重新解析"路径，绝不假装成功 |
| D 盘空间 | `CARGO_TARGET_DIR` 独立于项目，可随时清理 |
| 玻璃效果与预览图偏差 | 逐轮截图并排比对，按"匹配/差异/原因"清单迭代 |
